# Material rendering rebuild

The former material presets and their overlapping WebGL highlight, SVG surface, native region and per-material CSS effects have been removed from the active interface. The neutral interface keeps theme accents and optional Windows backdrop blur. Existing progress/connection shape and gradient choices remain independent. Saved old material preferences are retained but have no visual effect.

`tools/lab/webgpu-materials/` is a standalone WebGPU geometry and shader experiment for six reference styles. Serve the directory over localhost and open it in a WebGPU-capable browser to try it. It draws a synthetic background, not the desktop. It has not been integrated into the application and is not a finished material implementation. Device, shader and browser compatibility, appearance, performance, scaling, and screenshots must be checked on Windows x64.

A second, native experiment in `tools/lab/native-glass/` uses Direct2D paths, gradients and a resizable Win32 window; it requires only Windows graphics APIs at runtime. Its six shape variants are early geometry experiments, not the approved finished designs. It draws an opaque background and is not connected to the application or the Windows host backdrop. Windows CI compiles it and checks path construction; real-device visual and compositor testing remain necessary. Direct2D may select a software fallback; actual hardware usage needs verification on the target Windows machine. Direct3D plus DirectComposition remains a possible next step for custom shaders and compositor integration, and Skia is another candidate.

A separate Windows 11 Composition host-backdrop experiment is under `tools/lab/native-glass/backdrop.cpp`; it does not capture the screen or yet integrate with WebView2. Its first Windows Server 2025 runner screenshot showed a black client area rather than a visible backdrop. The cause is not established; device, compositor, policy and implementation differences still need investigation. A second capture with a colored reference window behind the test was also black, confirming that the sampled backdrop was not visible on this runner. The Windows 11 host-backdrop attribute requires build 22000 or newer, so Windows 10 needs a fallback.

A development-only integration now attempts to paint a Water Bubble background on the native HWND of a real download window. Launch the Tauri process with `MHG_EXPERIMENTAL_WATER=1` and use the desktop background mode. The UI enables the transparent surface only if native initialization succeeds, otherwise it keeps the normal background. The experiment is restricted to download windows, follows the current accent and light/dark selection, and creates/cleans up resources on the window thread. It does not capture the screen. Direct2D paints an opaque background: true Windows desktop backdrop, curved native window clipping, and correct WebView2 composition remain unverified. The native review workflow has an optional `experimental_water` switch that enables the experiment and captures both the WebView and desktop for manual review; a capture failure is recorded explicitly. The corrected review brought the real download window forward and confirmed that the native surface is visible, but it was opaque and showed rectangular corners outside its curved outline. An experimental matching HWND region now addresses the rectangular corners and follows resizing; it still needs visual verification at multiple sizes and DPI settings. Native window regions have hard pixel edges, so they do not guarantee the antialiased mockup appearance. Do not treat the experiment as a finished material or ship it as a selectable style without Windows visual and interaction tests.

## Architecture to investigate and build

* A single GPU composition pipeline should own each window's background, silhouette, bevels and material-specific surface geometry. The same geometry must govern clipping and interaction, so an extra rectangular layer does not extend over rounded or faceted edges. Keep controls and text readable above it. Derive tint from the selected accent once.
* Build Water Bubble as a vertical slice: deformable outline and smooth specular edges; then Ice Edge, Smoked Crystal, Frosted Layers, Aero Gloss and Prismatic Glass each need their own authored geometry and shader parameters. The generated reference images are visual targets, not implementation assets.
* Keep progress shapes and colors independently selectable, and connect the existing engine-driven indicators and transfer graph. A shape that follows a material can be a preset without forcing it.
* Prototype Windows Composition host-backdrop and Direct2D/Direct3D integration with Tauri's WebView2 window before committing to a production compositor. A compositor backdrop brush and a CSS backdrop filter are not proof that arbitrary desktop pixels are available to a shader. Direct2D exposes displacement effects, but feeding a real desktop backdrop into them alongside WebView2 needs a Windows prototype. Do not silently capture the screen to fake refraction.
* If desktop capture is needed, obtain user consent and investigate capture exclusion, recursion, protected content, mixed DPI, monitor changes, device loss and resource cleanup. Provide a clear fallback. Test both Windows 10 and 11 x64 where supported.
* Verify all windows, both light and dark modes, accent choices, resizing, text contrast, hit testing, GPU fallbacks and real download behavior on Windows. Compare screenshots directly with the references; a successful installer or shader compilation does not establish visual fidelity.
