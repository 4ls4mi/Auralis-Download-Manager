# Auralis release work in progress

This is a working checklist, not release notes. Do not describe a feature as shipped until it is integrated, verified and included in a published release. Current published version when this checklist was made: 0.3.38.

## Download recovery
- [ ] Verify dynamic segmentation for eligible ordinary downloads and preserve direct-to-file writes so completed ranges do not need a separate final merge. Confirm actual support and limitations for HTTP(S), FTP, proxies and resume.
- [ ] Verify the progressive segmented-video/HLS assembly (`c9748d0`) on Windows. The working copy keeps unrelated files, avoids overwriting a destination, checks newly saved piece hashes on resume, preserves changed pieces separately, and rejects incorrect byte-range responses. Older pieces without hashes remain unverified. Distinguish this from direct-to-file ordinary downloads and a possible final audio/video mux.
- [ ] Verify durable block-hash tracking and checked HTTP repair on Windows. The working copy can prepare a repair from an HTTP(S) target with a matching strong validator and range support, preserving a state backup and retaining intact ranges. It can refresh some expired redirected links on the same final origin. Browser-only, FTP and other sources still need recovery paths. Local hashes detect later changes; they do not authenticate the original data.
- [ ] Finish direct-download recovery and alternative source handling without promising that a non-range server can send an arbitrary missing range.
- [ ] Implement automatic torrent candidate discovery and evidence-based matching, asking or continuing according to the user's preference, and manual torrent/magnet fallback. The working copy offers user-initiated Internet Archive search, local .torrent and magnet comparison, and a selected-match handoff that preserves the original partial and persists torrent state before starting. Automatic discovery, the ask-or-continue preference and returning to direct download remain unfinished. The handoff currently refuses private downloads and downloads with an expected whole-file checksum. Searching discloses filename terms to the provider, magnet checking contacts peers, and candidate results do not prove a whole file matches. Internet Archive cannot search every torrent source.
  - Search parsing, redirect-host restrictions, oversized metadata and matching/mismatching multi-file torrent tests pass locally. The library can fetch bounded metadata from Internet Archive, compare available whole pieces, and retain up to three candidate metadata results. It reserves the local download while comparing and rechecks before staging. The progress window restores in-flight search/handoff status when reopened and displays the checksum limitation; browser tests use mocked native commands. The Windows shell, live integrated search, and magnet connections remain unverified. The native shell allowlist includes the repair commands, previously blocked before reaching the downloader.
  - Local two-peer torrent tests confirm that staged single-file and multi-file direct downloads reuse verified pieces, receive the remainder, and preserve their original partials. Multi-file boundary pieces are fetched rather than trusted without their neighbors. A failed-staging cleanup test verifies unrelated files are not removed. The local app-level test passed for consent and stale-selection rejection, conflicting metadata and failed-history-save rollback, persistence, restart and a local-peer transfer. Windows, live public search/peers, and interruption during transfer still require verification.
  - Local app and browser tests cover cancellation during preparation and immediately after handoff: a cancelled preparation does not start the torrent, and a committed handoff is stopped or removed from the queue. The original partial is retained in both cases.
  - Search skips candidates with invalid metadata or too many same-size files, rather than letting one unusable candidate block later results. Four local candidate-search tests pass; an integrated live-search test is still needed.
  - Automatic fallback must respect queue retry settings: queues can retry forever, so a single failed attempt cannot safely be treated as exhaustion. The preference needs an explicit trigger and disclosure of filename search terms and peer connections.
- [ ] Clearly show recovery status, torrent details and direct/torrent provenance in the download window and list.
- [ ] Verify interruption, corrupted data, resume, changes of source, and candidate mismatch paths end to end.

## WinUI 3 shell migration
- [ ] Replace the Tauri shell with WinUI 3 while retaining the downloader, browser integration, tray, updates, settings, all windows and existing user data. The isolated development shell in `winui-shell/` builds on Windows and maps material names to native Acrylic, Mica and Mica Alt; it is a backdrop preview, not a working downloader.
- [ ] Connect the real interface and migrate the native command/event/window bridge securely. The new `auralis-winui-bridge` has only start, stop, list, visual-state and single-download start/pause operations; its isolated local start/read/stop test passes with browser-compatibility disabled. Production browser compatibility, Windows bridge verification and all remaining operations are outstanding. The preview deliberately does not start the bridge or touch user data.
- [ ] Verify native backdrop appearance, readability, themes, resizing and multiple windows on the user's Windows configuration. Windows can vary or suppress system backdrops; Mica samples wallpaper while Acrylic can blur content behind the window. Do not describe a successful compilation as visual verification.

## Backup and appearance
- [ ] Complete full backup/export and restore UI, including preferences, download history, actual completed files and resumable partial files. Safely coordinate active downloads, queues, moves and extraction; preserve existing files. Include video, torrent, gallery and other multi-file cases; never silently omit data.
  - Restore name validation also rejects Windows console devices and superscript-numbered COM/LPT devices. The underlying filename check passed a local isolated test; the complete backup UI and Windows restore still need verification.
  - Snapshot writing now holds in-process downloader reservations while archiving; a local app test checks the busy-file refusal, the reservation during the archive write, its release afterward, and a completed-file round trip. UI operations, queue activity, non-engine writers and external processes still require coordination.
  - The working copy adds completed single-file videos without separate subtitles or fragments. It rejects unsupported queued torrents and other unsupported types even when their byte counter is zero, rather than exporting a history entry without the metadata it needs. Seven local app snapshot/restore tests passed, including the guard that refuses backup while private downloads are present.
  - Archive publication and restored-file moves use no-replace renames. Sixteen local backup-engine tests passed, including completed/partial round trips, corrupt input, cancellation, existing destinations and preserving unrelated files on a failed restore. Windows/filesystem verification remains outstanding.
- [ ] Verify full editable theme export and import on Windows. The working copy now exports the current palette, surface material, typography and independent indicator choices to a validated JSON file; local browser round-trip tests pass. Wallpaper files remain outside the theme file.
- [ ] Finish and verify material-driven translucency and native Windows blur, consistent theme colors and readable text, including white and black palettes. Check tiled and maximized layouts and avoid stretched toolbar buttons.

- [ ] Update the main project description and accurate feature/how-to guides in major languages, including Arabic. Only claim behavior actually implemented; explain any limits on resume, verification and torrent matching.
