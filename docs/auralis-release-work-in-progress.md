# Auralis release work in progress

This is a working checklist, not release notes. Do not describe a feature as shipped until it is integrated, verified and included in a published release. Current published version when this checklist was made: 0.3.38.

## Download recovery
- [ ] Verify dynamic segmentation for eligible ordinary downloads and preserve direct-to-file writes so completed ranges do not need a separate final merge. Confirm actual support and limitations for HTTP(S), FTP, proxies and resume.
- [ ] Verify the progressive segmented-video/HLS assembly (`c9748d0`) on Windows. The working copy keeps unrelated files, avoids overwriting a destination, checks newly saved piece hashes on resume, preserves changed pieces separately, and rejects incorrect byte-range responses. Older pieces without hashes remain unverified. Distinguish this from direct-to-file ordinary downloads and a possible final audio/video mux.
- [ ] Verify durable block-hash tracking and checked HTTP repair on Windows. The working copy can prepare a repair from an HTTP(S) target with a matching strong validator and range support, preserving a state backup and retaining intact ranges. It can refresh some expired redirected links on the same final origin. Browser-only, FTP and other sources still need recovery paths. Local hashes detect later changes; they do not authenticate the original data.
- [ ] Finish direct-download recovery and alternative source handling without promising that a non-range server can send an arbitrary missing range.
- [ ] Verify automatic search and torrent handoff on Windows. Under **Settings → Torrents**, choose **Off**, **Search and ask**, or **Search and continue automatically**. With search enabled, a terminal source failure can trigger an Internet Archive lookup after the engine finishes its direct retry and refresh paths and running queues exhaust their retries. The download needs saved direct-transfer bytes. A queue that can retry indefinitely keeps the direct attempt eligible and delays torrent recovery.
  - Search sends filename terms to Internet Archive. It screens candidates for a compatible file size and checks complete saved pieces against the torrent. Automatic handoff requires one candidate and one matching file, no failed candidate checks, and at least two matching pieces. It rechecks the selected pieces while copying them. Matching pieces establish the identity of those bytes. The remaining content depends on the selected torrent.
  - The progress window shows a failed direct transfer, search activity, matches, preparation, and the change to BitTorrent. If automatic search fails or produces no usable match, users can retry it, select a local `.torrent`, or enter a torrent metadata URL or magnet. Checking a magnet connects to peers. The app preserves the original partial and saves the recovered download in a separate folder. Handoff excludes private downloads and downloads with an expected whole-file checksum. Returning the torrent job to a direct download remains outside this flow.
  - Cancelling while a search is pending prevents its automatic handoff. Cancelling during preparation prevents the engine from starting the torrent. A torrent already committed is stopped or removed from the queue. Each path keeps the original partial.
  - Local two-peer tests have exercised single-file and multi-file recovery. They reuse verified pieces and fetch the remainder, including multi-file boundary pieces that could not be checked independently. App tests have covered stale selection, consent, failed save rollback, restart and cancellation. Verify the integrated Windows shell, live public search and peers, and interruption during transfer before closing this item.
- [ ] Verify interruption, corrupted data, resume, changes of source, and candidate mismatch paths end to end.

## Backup and appearance
- [ ] Verify full backup and restore on Windows. In the working copy, **Settings → General → Download backup** creates a portable archive with preferences, download history, queues, completed files and supported partial downloads. Restore uses a new directory and keeps files already on the destination computer.
  - Stopped public torrents preserve their selection and downloaded files. On resume, the torrent engine rechecks pieces against its metadata. Mixed direct-to-torrent downloads also keep the original direct checkpoint.
  - The archive includes tracked gallery files and saved video files, subtitles and supported checkpoints. It refuses private activity, credential-bearing torrents, incomplete account-based transfers, and legacy gallery partials with no recorded paths. Wallpaper and other preference paths may need updating on a new installation.
  - Stop downloads and queues and allow checks, moves and extraction to finish before starting an archive operation. The app holds its file reservations while the archive is written. Publication and restored-file moves use no-replace operations.
  - The installed Windows smoke test exports a completed download and a paused partial, restarts Auralis, restores the archive, checks the completed file, and resumes the restored partial.
- [ ] Verify full editable theme export and import on Windows. The working copy now exports the current palette, surface material, typography and independent indicator choices to a validated JSON file; local browser round-trip tests pass. Wallpaper files remain outside the theme file.
- [ ] Finish and verify material-driven translucency and native Windows blur, consistent theme colors and readable text, including white and black palettes. Check tiled and maximized layouts and avoid stretched toolbar buttons.
